# Learnings from the Manus cafe hackathon

The core principles of our architecture remain steadfast: connectors fetch facts, rules evaluate them deterministically, findings terminate in actions, human in the loop governs anything consequential, and the core remains sector agnostic. The hackathon served as a proving ground for these principles in a constrained, high velocity environment. The following nine patterns crystallized from our experience, demonstrating how robust systems scale from a hackathon prototype to production grade platforms.

1. Staged parse receipts at ingestion moments

**Why it works:** Parsing receipts in stages distributes work, reduces blast radius, and provides clear failure signals at ingestion checkpoints. It lets the system adapt to diverse document formats without blocking downstream processes. Incremental parsing yields faster feedback and easier debugging.
**Where it ports in the main app:** Integrate staged parsers into the ingestion service and attach them to thresholds or events. Each stage should expose a well defined contract so downstream components can proceed with partial results or retry as needed.

2. Findings must terminate in a real action (mailto order draft, CSV download)

**Why it works:** A finding without a prescribed action is a passive artifact. For real value, every result must lead to a deterministic operation that can be acted on or shared. This compels utility in every analytical step and closes the loop between insight and impact.
**Where it ports in the main app:** Update the findings engine so outputs carry a concrete action payload such as an email draft or a downloadable file. Enforce a gate that rejects outputs lacking a tangible next step.

3. Code owns numbers, agents own prose and research

**Why it works:** Deterministic rules govern numerical evaluation and fact checking, while agents handle synthesis, context gathering, and exploration. This separation reduces risk of numerical drift and limits hallucinations in critical metrics.
**Where it ports in the main app:** The orchestration layer should route numerical comparisons to the rule engine before context reaches generation agents. Maintain clear boundaries so prose and conclusions do not influence core numeric judgments.

4. Agent recomputed verification badges (3/3)

**Why it works:** Badges are recomputed by agents, not copied from sources, creating an active validation loop that surfaces internal logic gaps. This practice exposes bugs in definitions and strengthens trust in the verification process.
**Where it ports in the main app:** Evidence badges should be dynamically generated by agent verification steps rather than statically propagated. Use badge recomputation as part of the evidence pipeline.

5. Progressive disclosure beats plus a present mode deck

**Why it works:** Users can absorb complexity at their own pace. Progressive disclosure reduces cognitive load, while a present mode deck provides a focused view for stakeholders without overwhelming detail.
**Where it ports in the main app:** Implement default summary views in dashboards and require explicit actions to reveal deeper data. Include a dedicated present mode for key findings and narratives.

6. Frozen snapshots = zero standing dependency

**Why it works:** Freezing data at analysis time guarantees reproducibility and prevents divergence when sources update. It eliminates time travel in reports and supports reliable audits.
**Where it ports in the main app:** The reporting module should persist state using frozen snapshots rather than live queries for historical analyses.

7. Self-hosted artifacts instead of expiring CDN links

**Why it works:** Storing artifacts locally or in a controlled storage layer eliminates broken links and gives full control over lifecycle and access permissions.
**Where it ports in the main app:** Ingest all generated media (mp4, pdf) into self hosted storage and surface via stable URLs linked to artifacts rather than external CDN links.

8. Locality and personalization as welcome, not destination

**Why it works:** Localized context is useful to ease the user experience, but the core logic remains universal. Personalization should be layered on top without redefining the core rules.
**Where it ports in the main app:** Keep localization at the presentation layer while preserving a sector agnostic rules engine. Personalization should augment, not replace, core behavior.

9. Deploy discipline: ref-synced partial deploys and gating health probes

**Why it works:** Careful deployment with health gating minimizes risk and allows safe progressive rollout. It protects stability by preventing partial features from destabilizing the whole system.
**Where it ports in the main app:** Enforce a CI/CD process with health probes, feature flags, and ref-synced partial deployments to gate production releases.
